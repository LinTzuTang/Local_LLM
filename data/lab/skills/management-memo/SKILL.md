# 主管備忘／簽呈

## 原則

- **結論先行**：第一段就寫建議與需要主管做的決定（含期限）。主管只讀第一段也要知道該做什麼。
- 一頁內（約 600 字）。細節放附件或附表。
- 每個數字都要有來源與期間（例：「democo 資料庫，2026/01–2026/09，排除已取消訂單」）。估計值標「（估）」。
- 方案至少兩個，其中一個可以是「維持現狀」；寫出成本、效益、風險、時程。
- 不用流行語（賦能、抓手、閉環）；用具體名詞與動詞。

## 格式 A：決策備忘（一般主管報告）

```markdown
# 〈主旨：一句話說明要決定什麼〉

**建議**：〈一句話〉　**需要的決定**：〈核准／選擇方案〉　**期限**：〈日期〉

## 背景
〈2–3 句，為什麼現在要處理〉

## 現況與數據
| 指標 | 數值 | 來源／期間 |
|---|---|---|

## 方案比較
| 方案 | 成本 | 效益 | 風險 | 時程 |
|---|---|---|---|---|
| A. 〈 〉 | | | | |
| B. 維持現狀 | | | | |

## 建議與理由
1. 〈 〉

## 風險與因應
- 〈風險〉→〈因應〉

## 下一步
| 事項 | 負責 | 日期 |
|---|---|---|
```

## 格式 B：簽呈（需要正式核准時）

```text
主旨：擬〈動作〉，敬請　核示。
說明：
一、〈背景與依據〉
二、〈現況數據〉
三、〈方案與費用〉
擬辦：
一、〈建議做法〉
二、〈奉核後執行事項與時程〉
陳　〈主管職稱〉
```

## 收尾檢查

- 第一段有沒有建議、決定、期限？
- 數字有沒有來源、期間、單位？加總是否一致？
- 有沒有機密資料（成本、薪資、個資）？發送範圍要對應（見 data-privacy-check）。
